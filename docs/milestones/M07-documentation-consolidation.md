## M07.1 — Final code/status audit — **done (2026-08-13)**

Regenerate counts from code and run the full verification chain. Record the
current commit, schema versions, formats, card/precon counts, test totals, and
known limitations. Do not copy old totals from prose.

### Checklist

- [x] `docs/status-audit.md` is the audit, and **nobody writes it**. It is
      generated by `npm run audit:status` from `scripts/lib/status-audit.ts`,
      the CLI shell being `scripts/audit-status.ts` — the arrangement M01.5 set
      for repository tooling, so the audit's logic is tested like any other
      module.
- [x] Two halves, separated by `<!-- audit:derived:start -->` markers, because
      they are different kinds of claim. **Derived facts** are read out of the
      code and content they describe and are re-checked on every test run.
      The **run record** — commit, whether the tree was clean, the date, the
      Node version, the verification chain and its outcome, and the test totals
      — is a measurement taken once and deliberately not re-derived, since
      reproducing it means running the suite from inside the suite.
- [x] Every version is the constant itself, not a transcription: 11 play-contract
      versions, 14 recorded-artifact versions, 7 registries and the 4 pilot
      versions. Two of them had no constant to read — `manifest.json`'s and
      `summary.json`'s schema versions were integer literals at their write
      sites — so `MANIFEST_SCHEMA_VERSION` and `SUMMARY_SCHEMA_VERSION` now
      exist, carry the version history that was in those comments, and are
      exported. `CONTENT_BUNDLE_SCHEMA_VERSION`, `MATCH_STREAM_HEADER_VERSION`,
      `REFERENCE_POPULATION_VERSION` and the card-contract registry
      (`@tcg/rules-engine/card-contracts`, a new subpath beside
      `./test-fixtures`) were reachable only from inside their packages and are
      exported for the same reason.
- [x] Counts come from the same functions the product uses. Precon legality is
      `reviewPrecon` against `formatDatabase`, the call the server makes, so the
      audit cannot call a precon legal by a rule nothing enforces; the pool
      figures are `formatCardPool`; support is the M05.1 registry;
      contract coverage is the registry the M02.6 guard checks.
- [x] Known limitations are derived, not remembered: the keyword the engine does
      not execute, the mechanics no pilot values and no record observes, the
      per-set `implemented: false` count, the agent classes no pilot implements,
      the calibration fixtures with a recorded gap, and each precon's
      colour-legal pool against its deck size. That last one independently
      reproduces M05.5's finding — `goblin_warboss` has 41 legal cards for a
      40-card deck — from the content rather than from the sentence recording it.
- [x] A **question ledger** compares `docs/open-questions.md` against the plan's
      owner-decision list, in both directions and with the two directions kept
      apart: a question open in the file and absent from the plan's short list is
      ordinary and counted (23 of them), while a question the plan calls open and
      the file does not record is a contradiction and named. There is exactly one
      — **Q47 has no entry in `docs/open-questions.md`** — which is M07.2's work,
      recorded here rather than fixed here.
- [x] Drift is a failing test, not a discipline. `status-audit.test.ts` compares
      the committed document's derived half byte-for-byte with a fresh
      collection, and `npm run audit:check` does the same from the command line.
      A card, a schema bump, an ADR or an answered question therefore fails the
      suite until the audit is regenerated. `docs/status-audit.md` is in
      `.prettierignore` for the same reason the generated content bundle is.
- [x] Verification chain run in full: `npm run verify` at this commit, and the
      audit records that it passed, with 2057 tests in 101 files across the five
      Vitest projects.
