### Decisions recorded

- [ADR 0009](architecture/0009-bot-information-boundary.md) — a pilot receives a
  six-field observation containing the redacted `PlayerView` and the engine's
  `LegalActions`, and nothing else. The boundary is a type, not a convention.
- [ADR 0010](architecture/0010-seed-derivation-and-reproducibility.md) — seeds
  are hashes of a readable derivation path; identity is content-addressed; paired
  comparisons force common random numbers by _removing_ the differing term from
  the path.
- [ADR 0011](architecture/0011-telemetry-and-provenance.md) — telemetry is
  collected from the event stream during the match and attributed through causal
  source IDs; dead-hand has four distinct causes; raw records are the product.
- [ADR 0012](architecture/0012-experiment-storage-and-checkpointing.md) — one
  directory per experiment, JSONL streaming, resume by content-addressed match
  ID, search checkpoints carrying the already-bred next population.
- [ADR 0013](architecture/0013-statistical-contracts.md) — paired designs are
  analysed as paired; synergy is a four-cell difference-in-differences with a
  bootstrap that propagates every cell; multiplicity is reported and never used
  to suppress; metric names state their bounds.
- [ADR 0014](architecture/0014-unified-match-stream-and-reference-populations.md)
  — every experiment kind streams to one `matches.jsonl` with identity
  `arm + matchId`; a comparison's reference population is resolved once,
  content-hashed and replayed unchanged in both environments.
- [ADR 0022](architecture/0022-evidence-claims.md) — added later, by M05: what a
  run may be cited for, given the mechanics it exercised, the agent class that
  flew it, where its decks came from, and how the pilots calibrate.

### Hardening — the final report

The machinery ran long before its numbers meant what they said. Each row below
is a defect in what the laboratory _claimed_ to measure, not a crash; each has
regression tests, and the section numbers are
[PHASE4_HARDENING.md](PHASE4_HARDENING.md), retained because code comments cite
its contracts by number.

| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4    | The flagship comparison claimed Scorch 2 → 3 damage while the baseline already dealt 3, and silently dropped its targeting filter.                | The candidate now deals 4, keeps every other field identical, and a `declaredChanges` block is checked against both resolved pools **before any match runs**. Identical or undeclared differences are rejected.                                |
| 5    | `broad_cross_cluster_inclusion` was raised from the share of individual _decks_ running a card.                                                   | `analysis/inclusion.ts` measures coverage of eligible strategic clusters. Tiny and rarely-observed clusters leave the denominator. Deck share survives as `deckInclusionShare`.                                                                |

| 7    | Batches streamed to `matches.jsonl`; searches and comparisons accumulated in memory and wrote a final array.                                      | `reporting/match-store.ts` is the one raw store. All five kinds stream to it, dedupe by `arm + matchId`, resume behind a drift-checked header, and truncate a damaged tail exactly once.                                                       |
| 8.1  | `timesPlayed / timesDrawn` was named `playRatePerDrawn` and printed as a percentage, so "112%" was reachable.                                     | `playsPerDraw` (unbounded, printed as a multiplier) plus bounded `drawnCopyPlayConversion` and `gamesDrawnAndPlayedShare`, backed by new per-copy counters.                                                                                    |

| 9.1  | Paired experiments were analysed with independent-sample intervals.                                                                               | `analysis/paired.ts`: paired binary and paired continuous estimators, discordant counts, exclusions with reasons, stratified bootstrap intervals.                                                                                              |
| 9.2  | Synergy uncertainty came from the "both" cell alone.                                                                                              | A 2×2 difference-in-differences with a stratified bootstrap over all four cells. Any sparse cell returns insufficient evidence rather than a number.                                                                                           |
| 9.3  | Long flag lists carried no sense of scan width.                                                                                                   | `describeMultiplicity` reports hypotheses examined and expected false positives; Benjamini–Hochberg is available and never hides unadjusted values.                                                                                            |
| 10.1 | `opponent_field_sensitivity` was a public reason code nothing could raise.                                                                        | `analysis/sensitivity.ts` implements it, guarded by per-field minimums and non-overlapping intervals, and describes context sensitivity rather than a defect.                                                                                  |
| 10.2 | Card-level counter availability was inferred from cluster matchup counts.                                                                         | `analysis/counters.ts` requires controlled replacement evidence against a declared target, and reports `unavailable` — not zero — when it has none.                                                                                            |
| 10.3 | Pilot robustness needed hand-edited weights.                                                                                                      | Versioned perturbation profiles (`bot-interface/src/perturbation.ts`) and a `robustness` experiment kind that runs each profile on common seeds and never pools them.                                                                          |

| 12   | Reports lacked the provenance to audit them.                                                                                                      | `report.md` now leads with limitations, then a provenance table with configuration hash, card-pool hashes, reference-population hash, schema/seed versions, pilot versions, thresholds, and completed/failed/abnormal/excluded/resumed counts. |

#### An engine bug Phase 4 found

The pilots play far more matches than the Phase 3 suites did, and they deadlocked
the free-for-all: when the **active** seat was eliminated during its own turn —
an empty-deck draw, a concession, a timeout, or an effect that killed its
controller — `advance()` stalled on a turn nobody was left to take. Fixed in
`flow.ts` by handing the turn to the next living seat, with `handleTermination`
now advancing after its state-based checks. Three regression tests are in
`free-for-all.test.ts`. This only ever fired at three or four seats.

[PHASE4_HARDENING.md](PHASE4_HARDENING.md) §18 makes completion conditional, and
the last condition was documentary: "`CLAUDE.md`, project status, open questions,
ADRs, examples, and CLI help agree with the implemented state." Everything
technical held at the hardening commit; the documentary condition was met by

Two later milestones strengthened the same claim rather than merely preserving

calibration behind it rather than an author's sentence.

### Deliberate limitations, stated in every report

- Heuristic pilots are not good players. A result describes what these bots did
  with these decks under these rules, and nothing more. Since M05.4 a run says
  which **agent class** flew it and declines, by name, every claim that class
  cannot carry.
- No machine learning. Transparent heuristics and evolutionary deck search only —
  the telemetry is deliberately raw enough to support learning later.
- The analyser recommends investigation. It never edits card data, never picks a
  "best" patch, and its flags are `review_recommended`, `possible_interaction`,
  `insufficient_data` or `run_quality` — never "overpowered" or "balanced".
- Card-pair analysis reports pairs only. Triples explode combinatorially and
  cannot clear a support threshold worth having at these sample sizes.
- Most analytical views are 1v1. `playerCount` is carried through every schedule,
  record and bot contract and the runner seats four — M03's precon runs and M04's
  board telemetry are four-seat — but a view that needs a single opponent stays
  1v1 rather than attributing a result to whichever rival sorted first.

### Analytical limitations that remain

- **Sample sizes are small.** Most card pairs have an empty cell somewhere in the
  four-cell contrast and correctly come back as `insufficient_evidence`.
- **Card-level counter breadth needs a declared target.** Without
  `counterTargetDeckIds` and a replacement experiment behind it, the analyser
  reports `unavailable`.
- **Displacement needs replicates.** With one search replicate every card is
  `insufficient_evidence`, by design.
- **Opponent-field sensitivity is 1v1 only.**
- **Pilot robustness measures the profiles it ships with.** A conclusion labelled
  `stable` survived a specific, versioned set of bounded re-weightings — not
  every reasonable pilot, and certainly not a human.
- **`drawnCopyPlayConversion` can be `unavailable`.** It is `null` for records
  written before per-copy tracking existed, rather than a fabricated value.
- **Insertion controls are not built.** `includeInsertion` records a note when a
  base deck does not run the subject card; it does not construct the insertion
  variant.
- **No run in this build can reach a final balance standing.** That claim needs
  an archetype-aware or human-playtest pilot, and neither exists here (M05.4,
  M05.6).

### Unresolved decisions that belong to the game designer

Not blockers for the laboratory; they are what its output is waiting on. Q14
(what thresholds should gate a card change), Q15 (how a healthy plural meta is
measured), Q37 (should the pilots be better players), Q38 (when a multiplayer
balance run is worth it). All four are in
[open-questions.md](open-questions.md).

### Things worth knowing before extending it

- **The `prototype_core` fixture set is not a balanced format.** `trench_guard`
  (1/5 guardian + armored) is close to unbreakable in a small pool, and matches
  in a 12-card test format are decided by decking out rather than by combat. Both
  distorted early test fixtures before being understood. Wave 1 is the set to
  measure anything real against.
- **Statline buffs are pilot-fragile; cost reductions are not.** A bigger body at
  the same price makes the value pilot _less_ willing to trade it, so a stat buff
  can move a win rate in either direction. Fixtures that need a reliably strong
  card change the cost.
- Any module reachable from a worker thread must use erasable-only TypeScript
  syntax — no parameter properties, no enums — because workers load TS through a
  resolve hook rather than a build step.

## Milestones M01–M07 — the Wave 1 programme

Phase 4 finished the laboratory. These milestones made the thing it measures
real: a 155-card catalogue, four precons that can actually be played, and a
record of what any of it is worth. Each milestone file holds the tranche-level
detail and its checklist; [`history/milestone-log.md`](history/milestone-log.md)

### M01 — Truthfulness and verification — complete

[M01](milestones/M01-truthfulness-and-verification.md). The milestone that made
later claims checkable.

- An unfinished card makes a deck illegal **by name**
  (`deck/card_not_implemented`). The spectator runs such a precon only under
  `--allow-incomplete-cards`, which marks the replay and its telemetry
  `resultsValid: false`. No shipped deck triggers it any more; the path is still
  tested against a synthetic card and a doctored pool.
- Every card-pool and environment hash is taken over one canonical mechanics
  projection (`CARD_FIELD_KINDS`) that a new card field cannot be added to
  without classifying it. Older replays and frozen environments are refused
  rather than reinterpreted — the old hashes could not see `additionalCosts`.
- The in-app rulebook, glossary and contextual help describe the implemented
  ruleset. Doing it surfaced the contradiction that is now **Q47**.
- `npm run verify` became the whole gate: its `typecheck` step covers the
  workspaces and the root project, so `scripts/`, `vitest.config.ts` and
  `eslint.config.js` are held to the same strictness as shipped code.

### M02 — Remaining card mechanics — complete

[M02](milestones/M02-remaining-card-mechanics.md). Thirteen unfinished cards, five
new capabilities, and a closed catalogue.

- **Delayed effects** as first-class serialized state, bound once and never
  re-targeted, ended by a zone change and never surviving their turn
  ([ADR 0018](architecture/0018-delayed-and-replacement-effects.md)).
- **Revival arrivals** through the existing `move_card`: a revived card is a
  fresh permanent, Newly Deployed, reporting `entersBattlefield` and never
  `deployed`.
- **Values read off a statline** and **costs derived from the board**;
  `playCostOf` became the single answer to "what does this card cost right now".
- **Replacement effects** — exactly two rewritable moments (a battlefield
  arrival, a Ready Step readying), a three-stage Ready Step, and a replacement
  that is provably not a trigger.
- **Shared and divided choices** — a plural `chooser` asks every seat before
  applying anything; `divided` damage is a multiset with one entry per point.
- The set became `playtest`, which turns every card warning into a hard error.
  Every card has an executable behaviour contract and a coverage guard fails by
  name when one is missing; display-text drift is checked in **both** directions.
  The `deployed`/`entersBattlefield` review is recorded card by card in
  [entry-trigger-review.md](rules/entry-trigger-review.md); five of its cases are
  Q48 and were deliberately not decided.

### M03 — Precon integration — complete

[M03](milestones/M03-precon-integration.md). A precon became an identity rather
than a decklist ([ADR 0019](architecture/0019-precon-identity.md)).

- The builder browses precons for the active format, previews the whole list, and
  copies one into an ordinary saved deck with a fresh ID.
- The lobby sends `submit_precon { preconId }` and nothing else; the server
  resolves the ID against its own bundled content and reviews it with the same
  `reviewPrecon` the UI previewed with. There is no decklist on the wire.
- The simulator names precons the same way, and there every failure is fatal.
- Two things `environment.format` and `environment.sets` finally do: scope the
  card pool. They had been documented as selecting content and did nothing.

### M04 — Shared board telemetry — complete

[M04](milestones/M04-shared-board-telemetry.md) and
[ADR 0020](architecture/0020-board-telemetry-and-stall-definition.md). One
collector, two feeds, one answer.

- `@tcg/board-telemetry` defines board size, combat cost and trigger load once.
  A simulator batch feeds it live; the spectator feeds it a finished replay; the
  two are asserted equal on a real match rather than assumed.
- A quiet round says **why** it was quiet. `attack_opportunity` is emitted before
  declared attackers Exhaust, so it describes the board a seat decided against.
- **Q43 is answered and versioned.** A round counts toward a stall only when
  every living seat reached its attack step, every one could legally have
  attacked, and none did; three consecutive such rounds is a stall. The rule is
  data, travels with every verdict as `stallDefinition`, and a batch mixing
  definitions is refused a summary. Both traced four-seat precon matches classify
  `not_stalled`.
- **No Unit cap follows from any of it.** The unlimited battlefield is measured,
  not policed.

### M05 — AI reliability — complete

[M05](milestones/M05-ai-reliability.md) and
[ADR 0022](architecture/0022-evidence-claims.md). "Is this evidence?" became four
independent, derived answers.

- **Mechanic support registry** — every member of seven executable vocabularies
  classified along four dimensions, total over the schema, so an unclassified
  mechanic is a compile error. Support is derived from a card's structured data,
  not read off its `implemented` flag.
- **Pilots pay for what a card does** — a total pricer table over `EffectType`,
  Reactions priced rather than free, keywords the engine does not execute priced
  at zero, costs priced wherever they are paid.
- **Choice provenance** — a pending choice says why it exists and what selecting
  an option does, with no card identity attached
  ([ADR 0021](architecture/0021-choice-contract.md)).
- **Agent classes** — a pilot is an instrument, not a skill level, and a claim is
  carried only when every class in the run carries it.
- **Deck plans and construction provenance** — a deck can say what it is made of,
  and a run records where its decks came from rather than inferring it.
- **Calibration** — sixteen hand-authored tactical fixtures driven through the
  same view a networked bot gets, recording in both directions where a pilot
  misses the characteristic decision. Every batch opens with its calibration
  standing, derived from the agent classes that flew it and not from any config
  field.

### M06 — Token presentation — complete

[M06](milestones/M06-token-presentation.md). A board of a hundred Tokens became
readable without becoming a lie.

- **Q42 answered by measurement**: two Tokens share a tile only when their
  controller, definition and entire public interaction-relevant state match. The
  worst board Wave 1 produces — 117 `goblin_token` on one seat — is **two** tiles,
  64 Newly Deployed and 53 Ready. Grouping by definition alone would have hidden
  that 64 of them could not attack.
- A tile is **not** a targeting unit. Every action leaves through a member drawn
  by the same function that draws a lone entity, so there is one interaction path
  and one exact instance ID on the wire.
- The spectator draws the board with the same `groupEntities` over the same
  `instanceView` projection, so a field added to the grouping key reaches both
  surfaces at once. Analysis Mode cannot change grouping semantics structurally,
  and a **Stack tokens** toggle returns the pre-M06 board exactly.

| All state, actions, events, choices, results runtime-validated | Zod schemas in `src/schema/`; `serialize.ts` round trip           |
| All provisional values from one versioned rules configuration  | `config.ts`; nothing in the engine inlines a rule number          |
| Invalid actions never partially mutate state                   | `applyAction` works on a clone; asserted in `scenarios.test.ts`   |

| A CLI harness plays a scripted match and prints its event log  | `npm run demo:match`                                              |

The seventeen required scenarios are all in `scenarios.test.ts`, numbered to
match the specification so a missing case is obvious.

Two bugs the suite found: events emitted directly by an action handler
(`unit_deployed`, `attackers_declared`, `blockers_assigned`) never reached
trigger discovery, so `on_deploy`, `on_attack` and `on_block` silently never
fired; and the server marked a lobby `finished` before broadcasting, so clients
never learned the lobby had ended.

**Gaps recorded at the time, and where they stand now.** The continuous-effects
layer (Q2) and first-class player targets (Q23) arrived in Phase 3. `guardian` is
a real blocking obligation as of the Wave 1 ruleset, leaving `resilient` as the
only inert keyword (Q4). Commanders now deploy from the Command Zone and return
there on defeat, so the triggers that could never fire on a Commander now can.

```bash
npm run dev:server      # ws://127.0.0.1:8787, plus GET /health
npm run dev             # http://localhost:5173
```

Open the client twice, switch to the **Play** tab in both, create a lobby in one

Limitations that still hold: lobbies and matches are **in memory only**, so

### Phase 3 — Two-to-four-player free-for-all — complete

Delivered 2026-08-08. Rationale in
[ADR 0007](architecture/0007-free-for-all-state.md) (seat order, multi-defender
combat, player targets, elimination) and
[ADR 0008](architecture/0008-continuous-effects.md) (static abilities).

The confirmed schema answers landed before any multiplayer engine work: one
authoring form for deploy effects (Q1), the `staticAbilities` continuous layer
(Q2), structured activation `costs` (Q3, Q27), first-class player and source
targets (Q23, Q29), and stable seat order with ownership, control and
multi-defender combat. Card data is migrated on load, so older card JSON still
validates without hand-editing.

| Criterion                                                         | Evidence                                                   |
| ----------------------------------------------------------------- | ---------------------------------------------------------- |
| Two to four browsers create/join one lobby and finish a match     | `match-server.test.ts` — 2/3/4-seat tables end to end      |
| Multi-defender combat, triggers, elimination, victory determinism | `free-for-all.test.ts` §§3–9, 11                           |
| Server authoritative; no player sees another's hidden information | redaction suites at both engine and server layers          |
| Arrival order of independent choices cannot change the result     | `free-for-all.test.ts` §5 submits blocks in both orders    |
| Eliminated players spectate but cannot act                        | engine §14 plus the server's `engine/eliminated` rejection |
| Phase 1 and Phase 2 tests and behaviour intact                    | every earlier suite passes unmodified                      |

`free-for-all.test.ts` is numbered to match the fifteen required cases; items 13
(per-seat reconnection and idempotent replay) and 15 (1v1 unchanged) are
server-level and live in `match-server.test.ts`.

Three bugs the new tests found: concession never cleaned up in a multiplayer game
(`handleTermination` called `concludeIfOver` rather than the full state-based
check, so with three seats the loser's board stayed on the table); `card_drawn`
leaked another player's `instanceId`, letting a viewer track which physical cards
a rival kept through a mulligan; and a token-type card only ceased to exist if
the `isToken` flag was set, so tokenness could be lost depending on how the card
reached play.

**Limitations recorded at the time, and where they stand now.** Seat order is
still rolled from the match seed and players still cannot choose seats. Teams,
table politics and chat are still out of scope. Lobbies are still in memory only.
Reactions and a bounded priority window **were** added by the Wave 1 ruleset, and
Commanders **do** now deploy and return. Multiple blockers per attacker is still
unimplemented and is Q44 — `blocks` is a list of pairs, so it is not structurally
blocked.

## Player help and content system — complete

A cross-cutting milestone rather than a phase: it touches card data, the keyword
table and the web client, and changed no game rule. Designed in
[ADR 0015](architecture/0015-player-help-and-content.md).

| Area                | Delivered                                                                                                                                |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Keyword registry    | Consolidated into `@tcg/card-data`. `rules-engine` imports the `implemented` flag rather than duplicating it. `KEYWORD_INFO` removed.    |
| `@tcg/help-content` | Effect/trigger registries, glossary, rulebook schema and content, reference resolver, explanation service, content validator.            |
| Explanations        | `explainCard` — pure, deterministic, total over the effect union. No default branch, so an unhandled effect is a compile error.          |
| Rulebook            | Typed blocks in `rulebook.json`, with a closed block vocabulary and no markup. `RulebookPanel` renders block types, not rules.           |
| Lobby UI            | Rulebook button opening an accessible overlay with TOC, search, Escape, focus trap and focus restore. Lobby state survives.              |
| Match UI            | `? Help` toggle, safe inspection of hand, both battlefields, relics, Commanders and discard piles, with authoritative contextual status. |
| Authoring           | `npm run validate:content`, validated templates in [templates/cards/](templates/cards/), [ADDING_CARDS.md](ADDING_CARDS.md).             |

The consolidation exposed three player-facing definitions that disagreed with the
engine — `evasive` ("can only be blocked by Evasive units", when it cannot be
blocked at all), `siphon` (healing the Commander rather than the controller), and
`guardian`/`resilient` described as doing something while inert. These were
content corrections, not rules changes: no engine behaviour moved and no test
changed its expectation. `guardian` has since become a real blocking obligation
in the Wave 1 ruleset, and `resilient` is now the only inert keyword — barred
from a `playtest` or `active` set by the content build (Q4).

**Deferrals recorded at the time, and where they stand now.** The one-file-per-card
migration the ADR deferred **has happened**: cards live under
`content/sets/<set>/cards/<id>.json`, built into a generated bundle by
`npm run content:build`, and the loader API hid the physical layout exactly as
predicted, so no call site changed. Still deferred: no `text.rules` field
(`displayText` remains the single canonical rules text), no graphical card
editor, and the inspector still does not infer _why_ a card is unplayable —
where the view does not say, it says so.
